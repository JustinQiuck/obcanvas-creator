# 生成段融合计划

初稿：2026-09-12。修订：2026-09-14，纳入 G01–G08 审查结论，基于 `a4284f7` / 插件 0.8.0。状态：融合规则、开发小步骤与验收对应已整理，生成段功能尚未实现。

本计划定义生成段的对象归属与实施顺序，Drama 计划保留分镜方法、阶段 Skill 与质量门槛，完成状态统一见 [TODO](TODO.md)。本轮对照代码的冲突及修正见 [审查记录](validation/generation-segments-review.md)。下文新增字段和行为均为拟定设计，不表示现有插件已支持。

用户明确不引入参考片研究，重点融合生成段。借鉴 [qisi-video-remix 的分段方法](https://github.com/wyuzhi/qisi-video-remix/blob/main/SKILL.md)，独立适配到现有项目、镜头和素材关系。本轮不安装上游 Skill、不加入参考分析或故事改编入口；若后续复制上游正文，再固定提交并登记许可与改动。

## 1. 生产主线与职责

剧本 → 分镜预览 → 确认正式镜头与全片顺序 → 编排生成段 → 准备参考图、段内时间与提示词 → 冻结一次尝试并导出制作包 → RunningHub 外部生成 → 结果归入尝试 → 按镜头选片 → 按需截帧续接 → 剪辑。

| 对象 | 职责与关系 |
| --- | --- |
| 项目 | 管理全片镜头顺序、资产和制作进展；所有生成段归属于一个项目，全片顺序须在 GS01 新增 |
| 镜头 | 决定拍什么、为什么这样拍、动作边界、声音和计划剪辑时长；稳定 ID 不因分段改变 |
| 生成段 | 一次计划生成的内容范围，可含一个或多个镜头；记录覆盖顺序、分段理由、参考输入和目标生成时长 |
| 生成尝试 | 冻结某段某版本的计划输入，另记用户核对的实际执行信息与结果；同段允许多次尝试，每次可导回多个文件 |
| 镜头采用 | 记录从哪个视频中采用哪个实际区间；一个视频可服务多镜，一个镜头可有多个候选 |

“单镜制作包”成为只含一镜的生成段。生成段引用正式镜头，不维护第二份可编辑镜头正文；生成尝试保存不可变的输入快照。段内一镜不好，可以补拍该镜，不必重做整段。

### 顺序的唯一来源

0.8.0 的 `orderedShots`、`patchOrder` 和 `moveShot` 只处理场次的 `shotOrder`，不能直接当作跨场次的全片顺序。GS01 增加项目级 `editOrder`，只引用同项目正式镜头 ID；场次归属与全片位置分别表达，同一项目可编排 A1 → B1 → A2。

旧项目首次使用时，按现有场次列表及场次内顺序展示初始化草案，由用户确认跨场次排列后保存；不从扫描顺序、文件名或画布位置推断成片顺序。尚未确认时不执行跨场次相邻合并。启用项目顺序后，全片与场次列表都由它投影，原场次 `shotOrder` 仅保留为旧记录依据，不再作为另一个可写排序入口。缺少的新镜头显示待排，删除后残留 ID 不参与当前排序，恢复后按保留位置显示；正式入卡与追加顺序的部分失败可重试且不重复建镜头。

## 2. 编排规则

- 先确认镜头，再编排生成段。默认一镜一段；支持兼容相邻镜头的合并、已有分段的拆分。AI 仅提供建议与理由，用户确认后成为制作计划。
- 重大换景、时间跳转、造型变化、输入素材不兼容或动作过于复杂时优先独立生成。普通景别变化不强制拆段；多镜生成能力未验证时采用独立段。
- 当前制作方案每镜最多有一个主生成段；未分配镜头列为待编排。补拍段显式标记为补拍，引用原段和待补镜头，可以与主段重叠，但不争夺主段归属。补拍候选采用后，原段按所需镜头的当前采用情况汇总；不会因为视频来自补拍段而永远显示未完成。
- 默认按剪辑相邻镜头编排，不自动将相隔的 A 镜头并成一次长生成。生成执行顺序可与剪辑顺序不同，先做 A1 再做依赖它的 A2 不改变 A1 → B1 → A2 的成片顺序。
- 单镜动作超过实际生成约束时，提示用户调整镜头边界或使用支持该时长的执行方式，再重新编排。首版不承诺把多个视频自动接成一个长镜头，不静默截断动作或拆镜。
- 拆并、改序或调整覆盖范围先形成可检查的新方案，确认后旧方案被替代；仅当前方案参与主段唯一性与制作待办，历史段、尝试和视频保留可查。单段内容修订递增段修订号。跨记录应用保存前后映射与进度，中断时明确显示未完成编排，恢复前不把冲突覆盖显示为可生成。
- 调整段内内容只标记真正受影响的输入需复核，不自动替用户换片。仅改变独立段的外部执行顺序，不使其他段的文案或候选全部过期。

## 3. 时间与段内安排

| 时间 | 来源 |
| --- | --- |
| 计划剪辑时长 | 镜头设计，段内可汇总显示 |
| 目标生成时长 | 用户实际视频工作流支持的规格 |
| 段内计划时间窗 | 在目标生成时长内为各镜头安排起止时间及选片余量；提示词从零起算，用户确认后使用 |
| 实际采用区间 | 导入真实视频后选择的入点、出点 |

这些时间不要求相等。不按总时长除以上限机械分段，也不为凑满生成时长延长最终剪辑。例：两镜各计划剪入 2 秒，工作流生成 10 秒，可以明确规划 0–5 秒与 5–10 秒的素材窗口供选片；额外内容须说明用途并确认，不能自动填停顿或改动作。段内窗口须按镜头顺序、落在目标时长内，未分配时间须说明用途；无法满足动作或对白时报告冲突。实际生成的切点仍需导入后逐镜核对，不能直接把计划窗口写成实际采用区间。

上游的 15／30 秒选项不作为固定限制；实际能力未知时显示待确认。文字模型选择与视频生成规格分别管理。MV 的音乐时间点属于成片时间依据，不等于段内生成时间，也不等于源视频时间；不自动把短剧时长规则套到 MV。

## 4. 关键帧与制作包

每段应能看清：覆盖镜头、人物／造型／场景、真实参考图片及顺序、起止状态、目标时长和准备缺口。

- 资产身份图、场景图与本段起始图分别登记用途。起始关键帧的创作含义是第一镜开拍状态；执行端可能采用全参考、首帧或首尾帧模式，只有已核对的模式才声明对应控制能力。把图片上传为参考不等于模型必定从该画面开拍，也不强制每段必须使用首帧模式。
- 后续镜头需要独立图像控制时，只有实际工作流支持才提供对应输入，否则建议拆段。图片标签与实际挂图槽位对应。
- 每段视频提示词独立可复制，展开必要人物、造型、空间、动作、对白及声音；段内时间从零起算，不依赖“同上”。
- 视频提示词消费已确认镜头边界，不重新创作剧情；段内计划与生成规格冲突时显示具体问题，不静默调整。
- 制作包包含镜头范围、参考图清单、提示词与目标生成规格。已有图直接使用，缺图只影响依赖它的段。
- 保留 DS03 的“外部自行挂图”路径：可导出明确标有待挂图的包，但在用户核对外部图片和槽位前保持待准备，不显示已就绪。分镜方法决定镜头语言，视频方法负责表达已确认内容；选择模型或换分段方法不自动重写分镜。DS02 的阶段 Skill 选择、自定义和作品方向仍需交付，MV 不强制套短剧规则。

## 5. 尝试、结果与续接

RunningHub 保持外部执行，插件不提交、轮询或维护工作流。执行状态由用户登记，“已复制提示词”不等于“已生成”。

**首次交付制作包之前就保存尝试快照（GS02）。** 用户创建一次尝试，再复制或导出；重复复制同一尝试不创建新尝试，也不表示已执行。计划修改后需重新准备时创建新尝试，旧包仍可回查。用户登记已经外部执行后，该尝试才进入等待导入。

快照包含段 ID／修订号、镜头 ID 与所用内容全文及内容哈希、段内时间窗、提示词全文、引用图身份／用途／顺序／指纹、视频模式与目标时长。`FilmRecord.version: 1` 是格式版本，不能充当镜头内容修订号；新增修订号与输入哈希分别承担历史排序和过期检查。仅修改全片中无关镜头不使本次输入过期。图像指纹可以识别文件变化，不能在原文件被改写后凭空恢复旧图片；缺失或变化的历史输入须明确标记。

外部任务编号、链接、实际参数及外部改写后的提示词作为独立执行记录补录，带核对时间；更正保留上一条记录，不覆盖冻结的计划输入。未核对内容保持未知，不声称外部执行与计划一致。补录外部工作流的提示词增强结果不等于再次生成，后者新建尝试。

从具体尝试导回视频，成为候选，再把实际区间分配给镜头。可以保留段内部分镜头，单独补拍另一镜。采用决定仍由镜头与媒体关联保存，段状态仅汇总，不另存相互矛盾的采用结果。

首版每镜最多采用一个视频的一个连续区间，一个视频可被多个镜头分别采用；若需要多片段拼接，先显式调整镜头计划，不暗中扩展为剪辑器。实际入出点满足 `0 ≤ 入点 < 出点 ≤ 可验证的视频时长`。旧整视频采用保留并显示“已采用 · 区间待标注”，不能伪造出点；技术属性不可读取时保留决定并提示，不能宣称区间已核实。选片、时间区间与采用来源一起参加并发检查，新采用不覆盖旧文件或尝试。

现有“直接给镜头导入视频”入口继续可用，未关联尝试的旧视频标为来源未登记，不虚构生成历史。已创建尝试的外部结果也可先登记候选，缺少元数据不阻止归档，但仍需选片与实际区间验证。

续接帧记录实际源视频、时间位置、图像文件与目标段输入槽位。A2 需要承接 A1 时显式指定 A1 的真实帧，B1 不被误当作续接来源。更换源视频或相关区间后，只提醒实际依赖它的输入复核；计划尾状态不能冒充实际截帧。

## 6. 前端位置

项目内增加独立“生成段”工作区。分镜安排镜头，生成段安排每次制作，生成素材统一查看图片视频；画布按需显示段与镜头关系，正式内容只有一份。

操作顺序：确认镜头及全片顺序 → 检查一镜一段草案／调整拆并 → 选参考图并处理缺口 → 准备一次尝试并复制制作包 → 外部生成 → 从该尝试导回视频 → 按镜头选片 → 按需截帧续接。

状态分层汇总：未分配镜头显示待编排；段的准备情况为待准备／可生成；尝试区分已准备、用户登记已执行且等待导入、有结果、失败或取消。段卡显示已采用镜头数与未满足镜头，待选片、等待导入和需补拍可针对不同镜头同时存在。需补拍由用户选择或候选全部退回触发，不能因仅缺视频就强制补拍。所有所需镜头已有采用时显示“所需镜头已采用”，同时保留区间待标注、输入需复核或文件离线等独立提示；不能据此宣称可剪辑或续接。尚未实现的切片不提前显示可执行按钮。

## 7. 实施顺序与交付边界

GS 保留四个交付阶段，下表的小步骤用于实际开发和逐项验收；不新增另一套路线。按表顺序推进，每步先完成对应逻辑与隔离宿主验证，再进入依赖它的步骤。完成状态只在 [TODO](TODO.md) 勾选。

| 小步骤 / 对应阶段 | 交付范围 | 通过条件与当步能力边界 |
| --- | --- | --- |
| GS01a / DS02：正式镜头 | 阶段 Skill 选择/自定义、作品方向、预览差异与正式 ID 映射、确认入卡和恢复 | 先满足下述 DS01 质量门槛；重复应用不重建镜头，过期建议不覆盖新编辑，已有视频和布局保留；MV 不默认套短剧方法 |
| GS01b / DS02：全片顺序 | 项目 `editOrder`、旧顺序初始化草案、全片及场次视图投影 | 跨场次 A1 → B1 → A2 可保存并重开，跨项目引用拒绝；仅保留一个可写顺序来源；入卡成功而排序失败可恢复 |
| GS01c / DS02：手动编排 | 独立生成段工作区、一镜一段草案、相邻合并/拆分、主段/补拍的模型约束、方案替代与删除恢复 | 选择本次编排范围，不强制重做已有镜头；当前主段覆盖唯一，旧方案仍可查，中断不产生两个生效方案；此步只交付编排，不显示制作包或生成结果入口 |
| GS02a / DS03：输入准备 | 资产图片提示词、镜头关键帧文案、段实际参考槽位、执行模式和时长、段内时间窗、缺口定位 | 各字段按第 1–4 节归属保存；已有图/外部挂图均可用，未知能力保持待确认；时间窗不能冒充实际采用区间 |
| GS02b / DS04：可追溯制作包 | 视频提示词方法、完整段文案、创建尝试并冻结输入、复制/导出、实际执行信息补录 | 快照保存成功才交付包；重复复制不增尝试，外部改写不污染计划；手动核对 RunningHub 的图槽位/模式/时长/提示词是否再次增强；尚不宣称已具备结果到选片的完整流程 |
| GS03a / DS04、DS06：候选归档 | 视频导回具体尝试、文件身份与可读属性、失败后的重新关联；兼容直接导入镜头 | 一次尝试可留多个候选，重试不重复关联同一文件；关联失败保留已导入文件并可继续登记，旧来源未知不虚构尝试 |
| GS03b / DS06：选片与补拍 | 逐镜实际区间、单镜补拍操作、采用来源、部分采用汇总、旧整视频采用兼容 | 一个视频分别服务多镜；补拍采用仅替换目标镜头，原段正确汇总；旧区间不伪造，输入需复核与采用事实分开；候选和尝试保留 |
| GS04 / DS06、R4：真实续接 | 实际视频截帧、来源与时间记录、目标段槽位、连续/独立关系和依赖复核 | A2 明确依赖 A1 的实际帧，独立 B 段不误伤；源变化可追溯；导出新尝试使用确认后的输入，旧尝试保持不变 |

可选 AI 分段建议放在 GS02 手动编排与制作包验证后单独验收，不作为 GS03 的前置条件。它只提出分段与理由，由用户确认；不改正式镜头语言、不新增重复待办。阶段 Skill 与作品方向是原有 DS02 要求，不随该可选项延期。

GS01a 沿用 [Drama 计划第 7 节](drama-skills-integration-plan.md#7-验收方法与停止条件) 的 DS01 真实质量门槛：两份中性短剧本，同模型、同输入的最低基线与适配规则对照；两份适配候选均无关键事实/连续性错误、均至少 8/10，至少一份减少实质性修订且另一份不退步。未达门槛继续修正规则，不把 AI 正式入卡入口放入用户试用版；工程准备与现有手工镜头管理不因此停用。2026-09-14 已执行 4 次对照及 2 次修正规则复测，未达到质量门槛；GS01a 工程准备及详细问题见 [验证记录](validation/storyboard-gs01a.md)，正式试用版未更新。随后继续 4 次规则复测，累计 10 次，最终两份为 6/10、7/10，见 [后续验证](validation/storyboard-gs01a-followup.md)，门槛保持未通过。MV 保留独立方法/已验证自定义方法及明确音乐时间依据的要求，该短剧小样不代表 MV 质量验收。

DS05 资产身份／造型增强按实际依赖推进；超出当前状态表达能力时缩小范围或补足 DS05，不因生成段导入整套资产生成系统。各阶段就绪分别报告；GS02 制作包可交付不等于 GS03 的选片、GS04 的续接已经完成。

| Vault 记录与任务存储 | 按步骤接入读取/保存/冲突检查；GS01c 段笔记，GS02b 尝试快照与补录，GS03a 导入关联；新增类型时同步补齐项目扫描和删除恢复 |
| 项目导航及各工作区 | 分镜、生成段和素材分别呈现对应数据；阶段未完成不展示执行按钮；列表/画布不另存一份正式内容 |
| 媒体与参考关联 | GS02a 真实槽位/用途/模式、GS03b 区间与来源、GS04 截帧依赖；重命名、重定位和移除须同步检查新引用 |

正式段计划按项目归属的笔记保存，尝试与应用进度按项目 ID 关联的独立任务保存。新增字段随实际实现更新 [记录格式](record-format.md)，区分格式版本、内容修订和输入哈希；不得把本文拟定字段写成当前格式，也不全量重写旧目录。

当前项目删除只扫描正式 Markdown 笔记，不能假设它会自动处理新增 JSON 尝试。GS01c 将段笔记纳入项目删除范围；GS02b 同步处理尝试在项目删除后的历史可见性，不能等到最后补兼容。删除段只移除编排，保留镜头、视频和历史尝试；删除镜头后当前覆盖明确提示缺失，不从历史尝试自动重建镜头。删除项目时尝试作为历史保留且不显示为可执行任务；按同一项目 ID 恢复后可查，缺记录显示待恢复。共享媒体文件继续保留。

每次扩展新字段都要覆盖旧记录读取、删除中断/恢复及多视图并发，失败保留源记录与未完成进度。首次向试用资料库写新格式前验证匹配的数据备份和恢复路径；只回退插件包不能当作数据降级。文件写入成功、宿主验收和真实制作效果分别记录。

## 9. 审查结论到验收的对应

以下 G 编号对应 [8 项审查发现](validation/generation-segments-review.md)，每项都必须在指定步骤留下可复查证据。它们是验收条件，当前均未完成运行时验证；每步验证新增内容，不反复重跑全部旧宿主脚本。

| 审查项 | 落实步骤 | 验收操作与预期结果 |
| --- | --- | --- |
| G01 职责重复 | GS01a、GS02a–b、GS03b | 给同一镜头准备主段和补拍段，分别改执行文案；镜头正文/剪辑时长不被覆盖，两份尝试可追溯，采用只有镜头关联这一处决定 |
| G02 全片顺序缺失 | GS01b–c | 跨场次排成 A1 → B1 → A2，重开仍一致；改变生成执行先后不改成片顺序，未确认的跨场次草案不自动合并 |
| G03 快照时机与版本混淆 | GS02b | 保存失败时不交付包；连续复制两次仍为一个尝试；改计划后准备新尝试、补录外部改写，旧快照全文/哈希不变，无关镜头变化不误报过期 |
| G04 补拍覆盖与状态冲突 | GS01c、GS03b | 两镜段只采用一镜，另一镜补拍；主段覆盖不重复，采用补拍后原段所需镜头满足，旧方案和候选保留；方案应用中断只允许一个确认生效的方案 |
| G05 时间坐标混淆 | GS02a–b、GS03b | 两镜各计划剪入 2 秒、目标生成 10 秒，明确段内窗口和余量；不符动作/对白时报告问题；导回后手动选择真实入出点，不能直接复制计划切点 |
| G06 参考模式与外部挂图 | GS02a–b | 分别使用已核对的全参考/首帧输入及待外部挂图记录；槽位与能力说明一致，待挂图包可导出但不显示输入就绪，不静默换成文生视频 |
| G07 旧采用、直接导入与删除恢复 | GS01c 起随存储扩展验证，GS03b 完成区间验收 | 旧整视频采用显示区间待标注，直接导入无虚构尝试；删除并恢复项目/段/镜头，源视频不删除、历史任务不重建待办、无关项目不变；重定位不吞掉新增引用 |
| G08 旧路线与风格要求遗漏 | GS01a–c、GS02b | 在独立工作区操作，阶段 Skill 可选择/自定义且保存实际使用快照；用不同作品方向检查镜头决策，MV 缺专用方法或时间依据时明确提示；不出现参考片研究或 RunningHub 执行管理入口 |

首个完整工程验收使用少量中性镜头：一个含两镜的段、一个独立段、同段两次尝试各有候选、其中一镜补拍，再加入跨场次 A/B 续接。模拟文件可检查关系与恢复，不能证明多镜生成能力。真实 RunningHub 小样只核对用户选定的具体工作流和模式，按届时授权执行；没有验证的能力保持待确认。
