3. 在本地 `.local/test-vault/` 建立隔离测试资料库，仅放中性测试内容。该目录不进入 Git；插件源码和可复现测试夹具进入 Git。

## D02：记录约定与读取

预期新增：`src/model.ts`、`src/storage/vault-records.ts`；视实际需要添加记录读写的测试夹具。

- 固定场次 ID、镜头 ID、文件类型与格式版本。P0 的镜头只需要标题、所属场次、正文和参考素材关联；候选采用关系在 D06 实现。
- 标题和路径允许改变，记录 ID 保持稳定。用户界面显示中文名称，不要求直接编辑 ID。
- Markdown 正文保存镜头说明，属性保存结构化字段；布局只保存记录映射、位置、尺寸与视口。
- 使用宿主提供的属性操作能力与成熟解析工具，保留不归插件所有的属性和正文；损坏或未知版本记录明确提示，不能自动重建并覆盖。
- 约定笔记改名、移位或删除后如何刷新索引，保证读取同一记录时不会产生副本。

验收：中性夹具往返保存后内容不丢失；重命名仍能定位同一 ID；损坏记录不被写空。数据测试的通过仅证明对应逻辑，宿主事件需在 D03 实测。

## D03：双向读写与保存反馈

预期修改：镜头卡界面、资料库读写模块、自定义视图的订阅与卸载。

- 在画布视图编辑一张镜头卡的标题和内容，保存到对应笔记。
- 原生笔记或 Agent 修改文件后，视图更新；存在未保存编辑时比较变化，避免覆盖用户正在编辑的字段。
- 写入基于最新内容，只更新所属字段。异步处理和过期表单需要冲突检查，不能仅凭使用 Vault API 就宣称无并发问题。
- 保存状态至少区分“保存中、已保存、保存失败、内容冲突”；失败保留编辑内容并提供重试。
- 同一场次可以在两个标签页查看；正式数据共享，焦点和选中状态属于各自视图。

P0-A 验收证据：

1. 视图改内容 → 笔记更新；笔记改内容 → 视图更新。
2. 关闭重开 Obsidian，内容仍在。
3. 两个视图编辑同一记录时，不发生静默覆盖。
4. 模拟保存失败后界面保留输入并明确提示，重试能恢复。
5. 记录实际运行的检查、宿主版本和未验证项到 `docs/validation/p0-a.md`，该文件在验证发生时创建。
