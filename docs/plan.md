## 目标与范围

让用户打开一场戏就能知道：计划有哪些镜头，生成了哪些视频，哪些版本被采用，还缺什么，哪些选帧被用于后续镜头。

RunningHub 保持外部生成。工作台接收已有结果，不管理远程工作流定义、节点参数、升级、提交或轮询。已有网页版的 RunningHub 功能保持原状，本计划不要求删除它。

当前已实现独立插件入口、可靠保存、自由画布和库内素材预览，经隔离测试与用户授权，0.4.0 已安装到当前 Obsidian 资料库。原画布业务代码未修改。下一阶段的文字分析单独配置和验证；生图生视频效果、自动剪辑、付费生成和完整影片制作不属于该阶段验收。

以独立仓库 ObCanvas Creator 实施，按需复用本机既有项目 `/Users/aliceboy/项目文件/画布` 的组件，接入桌面版 Obsidian；由画布承担日常操作，Obsidian 保存项目资料。该本机路径仅用于标识复用来源，不作为插件运行时依赖。P 系列保留产品能力分类，执行顺序以 A01–A05 和 R 系列最新安排为准，不再先试用英文插件组合。

- 界面导航、字段标题、按钮、状态、空白页引导、保存反馈与常见错误均使用中文；沿用现有简体中文语言资源和画布主题。
- 用户通过画布完成导入、归类、采用、重做和选帧，不要求手写 Markdown 属性、JSON、查询语句或记住英文命令。底层格式仍可供 Agent 读取。

- 默认围绕当前场次工作：能看见镜头顺序与缺失项，点开镜头即看到参考图和候选视频；详细字段按需展开。
- 全中文可用性是验收条件：第一次进入、无素材、导入失败、选择候选和重开恢复等状态都不能让用户靠英文或代码猜下一步。

## 数据与界面原则

### 只维护一份正式记录

- 当前工作台以 Obsidian 库内文件为正式记录来源；画布只显示和编辑这些记录，内存状态可以作为缓存。
- 项目、场次、镜头说明和制作状态保存在 Markdown 与属性中，用户与 Agent 均可读取。显示名称中文，稳定 ID 不因重命名变化。
- 画布布局、节点映射等显示数据存为独立 JSON，不复制一份镜头正文或采用决定。
- 视频、图片登记真实文件位置。临时播放地址、缩略图缓存、文件不可访问等状态不替代正式记录。
- 原始素材默认保留原位；被用户选入项目的文件可以复制进资料库，或关联外置硬盘路径。正式项目采用哪种方式是导入前需要确定的设置，不能自动移动源文件。
- 外置磁盘未挂载时显示“素材离线”和重新定位入口，保留镜头与采用关系。
- 保存失败时明确显示未保存；多个视图、笔记编辑或 Agent 修改同一记录时，不用旧缓存覆盖新正文。

### 最少的数据关系

| 对象 | 记录什么 |
|---|---|
| 项目／场次 | 当前剧本来源、场次目标、镜头顺序 |
| 镜头 | 稳定 ID、场次、拍摄内容与理由、景别机位、计划参考、衔接意图 |
| 媒体 | 稳定 ID、真实文件位置、可获得的时长与尺寸、可选生成来源 |
| 镜头素材关联 | 镜头 ID、媒体 ID、候选／采用／退回决定、实际入出点、退回原因 |
| 选帧 | 图片位置、来源媒体 ID、来源时间、关联采用版本、参考职责、目标镜头 |

一个视频可供多个镜头使用；一个镜头可有多个候选视频。素材版本与采用关系分开保存，切换采用版本不覆盖旧文件。

镜头板按成片顺序排列，不能把自由画布上节点的左右位置自动当成正式顺序。拖动排序是明确操作，并同步更新正式顺序。

### 用户只补需要判断的信息

- 导入时尽量自动记录技术属性；素材可通过拖到镜头上直接归属，不要求重复填写表格。
- 用户判断镜头意图、素材是否采用、采用区间和选帧用途。
- 工作流链接、原提示词等为可选来源信息，不要求用户整理 RunningHub 内部节点或提供 API Key。
- “缺素材／待选片／待重做”由镜头计划、候选和选择记录推导；不能用文件数量推断镜头已完成。
- 生成成功、文件导入、素材采用、进入正式剪辑是不同事实，界面不能混称为“完成”。
