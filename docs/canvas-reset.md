# 自由画布改造：从试用反馈重新确定主界面

## 已确认的方向

用户试用 0.2.0 后确认：保留原「画布」自由摆放、连接素材的操作方式，将影视制作流程放进画布，Obsidian 保存背后的文件。当前镜头表单不能作为最终工作台。

原来的 P0/P1 验收只证明读写、布局和候选管理通过技术验证；不代表用户已经能顺利完成制作。D07/D08 暂缓，先完成下面的 R 系列切片。保留已有镜头记录、采用决定和未保存草稿。

## 用户实际如何工作

1. 把与 Grok 讨论好的剧本粘贴为剧本卡，也可以关联已有笔记。
2. 从剧本点击“整理拍摄资产”，检查人物、场景和道具清单，确认后创建或复用资产卡；再绑定人物照片、平面图、场景或道具参考图。可先放素材再关联，无需先创建镜头。此流程按 [A01–A05](agent-assets-plan.md) 实施，0.4.0 已实现，真实模型提取效果待配置后验证。
3. 从剧本整理出镜头卡。拍摄理由、景别、机位和提示词可以由 Skill 提出，用户审核；不能把空白字段当成提供了导演帮助。
4. 为需要生成的镜头指定参考图／关键帧。自由连线表示用途，成片顺序由独立顺序字段决定。
5. 带着该镜头的提示词与参考文件去 RunningHub 生成。工作台不管理工作流，也不发起调用。
6. 把生成视频拖回画布，连接到对应镜头，比较候选并选择采用、重做或待定。
7. 对需要续接的镜头选帧，记录来源视频、采用区间、来源时间和目标镜头；换机位允许独立参考图。

流程提示用于帮助定位，可以先放图片、先整理视频，也可以随时回到剧本。不得用强制向导锁住画布。

## 主界面与交互约定

- 画布占据主要空间；顶部只保留项目/场次、添加、待办和视图工具。移除常驻的大表单和重复镜头列表。
- 剧本、人物、场景、镜头、关键帧和视频在画布上是可辨认的对象。素材显示真实缩略图，不用文件名表格代替素材。
- 点击对象时才打开可关闭的详情栏；空白区域回到总览。画布拖动不改变成片顺序。
- 连线带中文关系名称，如「剧情拆分」「人物参考」「场景参考」「起始帧」「视频候选」「续接帧」。连线必须能创建和移除；移除连线不删除素材。
- 待办定位到具体对象和缺失动作，例如「镜头 02 缺少起始帧」，而非只有数量。
- 编辑保存提供明确反馈；普通切换不应仅因标题未保存就让大部分按钮失效。实现自动保存时仍须复用已有冲突检查、错误保留与草稿恢复。
- 正式内容、素材关系与采用决定只有库内一份记录。布局只存位置、尺寸、视口和节点映射，浏览器持久化不能成为第二个项目数据库。

用户确认 R0 方向后已授权更新插件实操。R1 已随 0.3.0 接入并通过验证，R2 的基础关系/待办/切换保存一并接入；完整 R2–R4 仍未完成。R0 不接 AI，不写真实资料库，刷新后清空预览编辑。它用于检查操作方式，不能作为存放正式剧本的工具。

最新优先级：先完成跨 R2／R3 的 [AI 助手与资产准备 A01–A05](agent-assets-plan.md)，不等待完整 R2 的续接语义。保持本页的自由交互方式，RunningHub 继续外部生成。该阶段已在 0.4.0 实现并通过 [隔离实机验证](validation/a-assets.md)，真实服务与用户验收待完成。

## 原型与源码依据

原型入口：[自由画布操作预览](prototypes/free-canvas/index.html)。在仓库根目录运行 `python3 -m http.server 4189 --bind 127.0.0.1 --directory docs/prototypes/free-canvas`，打开 `http://127.0.0.1:4189`。端口被占用时选择空闲端口，不停止其他项目服务。

原型代码独立编写；视觉使用已引入的 `src/canvas/theme.ts` 暖色画布配色，保留 [MIT 许可](../licenses/infinite-canvas-MIT.txt)。本轮未复制原网页文件。后续提取 `canvas-node.tsx`、`canvas-connections.tsx`、`canvas-toolbar.tsx` 时仍须按 [源码复用记录](source-reuse.md) 记录实际工作区快照和适配，不整体搬入带生成服务的 `project.tsx`。

验证结果见 [R0 原型验证](validation/r0.md) 与 [R1 插件验证](validation/r1.md)。
