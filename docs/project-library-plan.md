# 剧本项目库与独立工作区

日期：2026-09-12。版本：0.7.0。

用户反馈：资产整理、Skill、分镜与关键帧都挤在剧本卡片中，缺少一个剧本项目拥有全部资产的概念。本次优先修正项目归属和操作入口，DS02–DS06 继续按原验收门槛推进。

## 产品结构

Obsidian 资料库可以保存多个剧本项目。一个项目包含多份剧本（场次或段落）、人物、场景、道具、镜头、关键帧和图片／视频。资产属于项目，剧本和镜头引用资产；同项目跨场次复用保持同一 ID。

| 入口 | 职责 |
| --- | --- |
| 剧本项目库 | 创建、进入项目，查看剧本／资产／镜头数量；项目内可改名 |
| 剧本 | 阅读、粘贴和编辑正文，显示关联数量和工作区入口 |
| 资产库 | 汇总项目全部人物／场景／道具，搜索分类、创建、绑定图片、勾选使用该资产的剧本 |
| 资产库 → 从剧本整理资产 | 选择本项目剧本及 Skill，提取清单，确认复用或创建 |
| 分镜 | 选择本项目剧本，在独立宽区域生成和编辑分镜／起始关键帧预览 |
| 生成素材 | 汇总持有图片／视频的项目记录，导入结果、查看素材和候选决定 |
| 画布 | 在项目内切换场次，自由摆放和关联卡片；剧本卡中不再显示 AI 长表单 |

## 数据兼容

- 项目也是 Markdown 记录，类型为 `project`。新增记录保存 `projectId`；人物、场景、道具、素材和关键帧可只归项目，无需先建场次。
- 旧卡片无 `projectId` 时，通过所属场次推断；旧场次也无该字段时，归入 `legacy-project`，显示为“原有剧本项目”。只读归类不重写、移动或复制旧笔记、图片、布局和任务。用户修改项目名时才增加项目笔记。
- 现有目录和文件位置继续保留，项目库按记录归属组织。读取报告缺失项目或场次与项目不一致；创建、关联、AI 上下文及同名复用均检查项目范围。
- 每项目默认资产 Skill 单独保存；旧默认作为未配置项目的回退值。剧本选择和历史快照保留，自定义规则库及模型服务配置继续共享。
- 工作区位置存入 Obsidian 视图状态，多个视图独立。切换前保存正文与预览，失败保持当前内容；删除沿用回收站。

## 验收范围

两个项目的同名人物独立；同项目两份剧本复用同一资产；剧本编辑与画布剧本详情不显示资产或分镜长表单；独立工作区可完成提取、确认和分镜编辑；图片绑定、素材导入与删除后媒体保留可用；完整重启恢复项目和编辑，旧项目笔记逐字不变。

结果见 [0.7.0 验收](validation/project-library.md)。本次不提供跨项目搬迁、自动拆旧库、合并或删除整个项目；分镜仍是独立预览，正式镜头入卡与截图续接继续按 DS 计划推进。
