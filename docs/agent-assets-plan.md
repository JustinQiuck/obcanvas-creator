# AI 助手与内置 Skill：剧本到拍摄资产

日期：2026-09-11。状态：A01–A05 已实现并通过 [隔离实机验证](validation/a-assets.md)，开发版本为 0.4.0。真实文字服务与用户操作验收仍待完成。

## 目标与本轮范围

用户已经能看懂自由画布，但导入剧本后，不知道该准备哪些素材、素材应当绑定在哪里。本阶段完成一条可实操的流程：

**配置一个文字模型 → 导入剧本 → 整理拍摄资产 → 检查并确认清单 → 绑定参考图 → 看见还缺什么。**

借鉴 huobao-drama 的“按任务加载 Skill、通过项目工具读写数据”结构。本仓库独立编写技能规则、输出格式和适配代码；不复制其 Skill 正文、Agent 框架、工具实现或业务后端，不建立对该项目的运行依赖。

用户已进一步授权“执行计划”，并选择通用接口。实现采用 Chat Completions 兼容格式；本次真实 HTTP 验证使用本机模拟服务，不调用付费模型。

### 首版包含

- 一个中文 AI 助手设置页，一套文字模型连接配置。
- 一个随插件打包的“拍摄资产提取”Skill。
- 剧本卡的“整理拍摄资产”入口及可修改的结果确认界面。
- 人物、场景、道具资产的创建、复用与剧本关联。
- 资产卡的参考图绑定、用途标记、用户确认与缺失项定位。
- 与现有记录、草稿、素材和采用决定兼容的保存与恢复。

### 后续范围

分镜建议、景别与机位理由、静态关键帧提示词、视频动作提示词和单镜制作包继续属于 R3 后续切片。资产制作提示词也留待后续 Skill；本阶段缺图时记录待准备，用户可继续使用已有外部工具。

暂不做通用聊天窗口、多 Agent 编排、Skill 市场或任意脚本执行、外部 Codex/ZCode 会话接入、多套模型路由、图像理解及生图生视频。参考图片在本阶段用于本地绑定，不发送给文字模型分析。

RunningHub 的生成提交、工作流、密钥及轮询仍保持在插件之外。本阶段新增的是文字分析模型配置，与 RunningHub 生成服务分开。

## 用户操作与界面

| 位置 | 操作 | 看得见的结果 |
| --- | --- | --- |
| 设置 → AI 助手 | 填写服务地址、模型名称、密钥（服务需要时），主动测试连接 | 中文显示可用或失败原因；未配置仍能正常使用画布 |
| 剧本卡 | 点击“整理拍摄资产” | 保存当前剧本后，读取该剧本和项目已有资产；显示正在整理、取消和错误反馈 |
| 资产清单 | 按人物、场景、道具检查 | 每项显示名称、剧本依据、已知特征、待确认信息，以及新增或复用建议 |
| 资产清单 | 改名、合并本次重复项、忽略不需要的项、选择已有资产 | 用户无需编辑 JSON；合并只处理本次清单，不批量合并已有项目笔记 |
| 资产清单 | 点击“确认并生成资产卡” | 创建或引用对应资产，画布自动显示与剧本的关系；已有卡片位置保留 |
| 资产卡 | 点击“绑定参考图”，拖入图片或选择库内文件 | 图像显示在所属资产中，标记用途，可从多张候选里确认使用哪些 |
| 查看待办 | 点击“待确认信息”或“待准备参考图” | 定位具体资产，给出可执行动作，绑定后更新缺失项 |

保持自由画布为主界面。整理过程在可关闭的侧栏内完成，不强制用户逐步通关。允许先放素材，再在清单里选择已有资产；没有模型配置时也可手动建立和绑定资产。

“上传”在本阶段指复制图片到资料库或关联已有库内文件，界面明确用“导入参考图／关联库内图片”。不自动移动源文件，不默认上传到模型服务。

## 三层结构

### 1. 模型连接与任务执行

用户只配置一个 AI 助手。代码将文字模型连接、任务执行和画布读写分开，便于之后更换模型，不要求用户理解 Agent 框架。

- 首版适配一种明确的文字接口协议，具体服务和模型在 A02 开始前核实。地址与模型名可配置，不宣称所有兼容接口均可用；首版不依赖模型支持工具调用。
- 任务执行器先用本地读取工具收集剧本和已有资产摘要，再加载指定 Skill，要求模型输出结构化的提取建议。工具参数、输出和关联目标均由插件校验。
- 模型阶段只有读取和提出建议的能力；确认后的正式写入由插件执行。模型不能任意修改资料库，也不能通过剧本文字或返回结果扩大工具范围。
- 每次运行记录任务 ID、目标剧本 ID、输入版本、模型标识、Skill 版本、状态和诊断信息；任务结果与当前场次切换解耦，迟到的结果不能写入另一个剧本。
- 首版同一资料库同时执行一个提取任务，重复点击不能重复提交。超时、取消、插件卸载和窗口关闭均停止接收该次结果；已发出的远端请求可能仍执行，界面不声称取消必然撤销计费。
- 认证失败、接口不兼容、网络异常、输出截断或格式错误分别显示中文原因。失败保留原项目，不静默截短剧本，不自动重试收费请求；超出已验证输入范围时提示缩小本次剧本内容。

连接测试必须由用户点击触发，使用最小中性文本，不发送项目内容。分析任务在入口说明将发送所选剧本和已有资产的必要摘要，不扫描资料库其他笔记。

非敏感设置与现有草稿通过同一保存入口合并写入，防止现有 `flushDrafts()` 覆盖新增设置。密钥不进入项目笔记、日志、导出包或 Git；A02 核实当前宿主的凭据保存能力，若无法验证可靠的持久保存方式，首版只在当前会话持有密钥并明确提示。

### 2. 内置 Skill

拟定目录为 `skills/production-asset-extractor/SKILL.md`，由构建流程打包，发布产物不依赖用户电脑上的全局 Skill 目录。小型注册表保存 Skill ID、版本、适用任务和输出格式版本；首版只有一项，在任务启动时加载。

首版 Skill 独立编写以下规则：

1. 只整理选中剧本实际涉及的拍摄资产，保留可回查的原文依据。
2. 提取人物身份与已知外观；性格不能直接当成剧本已经确定的长相。缺失年龄、服装、材质等信息保留“待确认”，不强行扩写。
3. 提取场景空间、出入口、陈设和已知时段／光线。同地点的不同时段或状态需要区分需求，不能仅因名称相同就合并，也不能一律复制整个场景。
4. 提取需要保持外观一致的叙事道具。按实际剧情需要判断，无固定数量上限；没有需要的道具可为空，不把所有家具都拆成独立资产。
5. 查阅项目已有资产，提出复用候选。别名、近名、同名不同人等情况交由用户确认，名称匹配不能直接改变已有身份。
6. 区分剧本明确事实、建议准备的参考种类、尚缺信息。参考需求可建议主参考、妆造、平面图或空间反向视角，但不强制每项制作全套图片。
7. 输出提取清单，不输出已经完成的绑定、镜头或采用决定。仅凭文字模型无法判断用户图片是否符合角色或场景。

输出由独立校验器检查类型、数量与长度边界、原文依据和已有资产 ID。未知 ID、编造的来源段落或不符合格式的结果不能直接转为正式卡片。用户在普通字段里处理疑问，无需修复模型 JSON。

首版 0.4.0 未开放自定义 Skill。0.5.0 已按 [分阶段 Skill 计划](skill-selection-plan.md) 增加资产 Skill 选择、项目默认、自定义编辑和 Markdown 导入导出；依然不执行脚本或加载外部资源。插件更新或规则修改不自动重跑、也不改写已确认资产。

### 3. 项目读取、确认与绑定工具

首版只实现任务实际需要的能力：读取选中剧本、列出当前项目资产、保存提取草稿、应用用户确认的清单、绑定或移除参考图片。优先复用 `VaultRecords`、`VaultMedia` 和现有编辑冲突机制。

提取结果首先保存为“待确认的任务草稿”，与正式资产笔记分开，并能重开恢复。草稿保存 AI 建议和用户修改；确认后记录资产 ID 映射，避免再次打开或重试时重复创建。

## 资产身份、来源与状态

当前以资料库内的“影视项目”作为单一项目范围，不新增多项目管理。现有 `person`、`setting` 继续使用，新增 `prop`（道具）；`scene` 仍指场次，`asset` 仍指通用素材，不能混用。

| 信息 | 保存规则 |
| --- | --- |
| 资产身份 | 稳定记录 ID；重命名和复用不创建副本 |
| 剧本使用关系 | 剧本通过资产 ID 关联人物／场景／道具；画布连线从正式关系生成 |
| 来源依据 | 提取任务保存剧本 ID、输入内容版本、原文片段定位；确认映射可追溯到对应资产 |
| 外观与需求 | 区分已确认描述、待确认信息、需要的参考用途；复用建议不覆盖用户已确认的描述 |
| 图片绑定 | 复用媒体 ID 与库内相对路径，另存用途和用户确认；临时预览地址不作为正式路径 |
| 任务记录 | 保存待确认内容、输入版本和应用进度；已确认后的正式资产内容只由资产笔记维护 |
| 布局 | 只存节点位置和视口；不复制资产描述、绑定状态或确认决定 |

现有 0.3.0 的非场次卡片都要求 `sceneId`，画布也按场次过滤。首版保持已有记录和 ID，不批量迁移：新资产仍记录创建场次，但资产检索覆盖本项目全部人物／场景／道具。其他场次的剧本引用同一资产 ID 后，画布显示该引用资产，无需复制笔记。创建场次不再限制可复用范围；布局仍按各场次保存显示位置。

资产确认程度与图片准备程度分开显示，待办据此计算：

- **待确认信息**：存在影响本次制作的未决描述；不强制填满所有外观字段。
- **待准备参考图**：已确认的参考需求还没有图片。
- **待检查参考图**：已导入候选，用户还没确认使用。
- **已绑定参考图**：所需用途已绑定可访问的图片，并经过用户确认。
- 图片缺失／离线为独立问题：保留绑定记录，显示重新关联入口，不能继续显示无问题的已就绪。

旧图片关联不会自动视为“用户确认使用”；新增确认动作不改变镜头的视频采用逻辑。通用人物照片、场景图和道具图是可复用资产，镜头关键帧还需要具体构图与动作状态，本阶段不将参考图自动标记为镜头起始帧。

## 确认与保存规则

- 点击提取前复用当前编辑器保存动作；保存失败或有冲突时保留输入，不提交模型。输入版本取自成功保存的剧本。
- 结果返回后或应用前发现剧本已变更时标记“剧本已更新，需重新核对”；禁止直接应用过期清单，保留用户整理结果供对照。
- 创建资产、关联剧本前重新核对目标 ID 与当前笔记。已有资产发生并发修改时展示差异，不用旧结果覆盖新内容。
- 首版的“合并”只合并未写入的清单项；已有资产复用只增加关系。确需修改已有描述时单独显示待确认差异，不能因提取顺便重写。
- 多文件写入不假定具有事务性。先保存确认草稿和预分配 ID，再按条目记录应用进度；中途失败显示哪些已保存、哪些待重试。重试复用原 ID，不复制已创建资产、不回滚覆盖用户后续编辑。
- 重复提取保留已有正式资产和图片，提供新增／复用／忽略清单；本次没有提到的旧资产不会自动删除。
- 解除图片绑定或剧本关系只修改关联，不删除图片或资产笔记。旧镜头正文、未知属性、视频采用与未保存草稿必须保留。

## 验证与完成标准

实现按以下层次分别记录证据；已运行结果见验收记录，尚未进行的真实服务和用户测试不能标记完成：

1. **数据与逻辑**：重复身份、同名歧义、空道具、待确认外观、无效输出、跨场次复用、失效输入版本、部分写入重试、图片缺失、设置与草稿共存。按改动执行类型检查、构建及相关测试。
2. **隔离 Obsidian**：用中性剧本、已有角色和合成图片，走完整流程；检查两场次共享资产、改名、取消／失败、重开和旧记录兼容。模拟模型的通过不算真实接口可用。
3. **真实文字接口**：服务、模型及凭据准备好后，由明确的测试动作发起中性文本调用，记录成功、失败和输出质量；不得把本计划视为任意收费调用授权。
4. **用户操作验收**：能指出“这个剧本用了谁、在哪里、需要什么道具、绑定了哪些图片、还缺什么”，并完成一次绑定。技术验证通过不能替代用户实操反馈。

开发完成的判断是：在已验证的文字接口下，用户能完成上述流程且数据保存可靠。真实模型未验证时明确标注该限制，不能宣称 AI 接入完成；新版本安装与用户操作验收分别记录。
