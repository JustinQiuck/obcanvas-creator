### 审阅评分与需修改镜头

按计划五项各 0–2 分：事实/对白、景别机位理由、静态首帧、连续性、可继续制作。评分由本次代理逐镜审阅，不是用户创作批准，也不是统计评估。需修订数按“至少一项实质性问题的镜头”去重；不把减少总镜头数直接当作质量提升。

每镜主要修订依据（镜号按各响应顺序）：

- 惊喜基线：1、3、4 的首帧缺机位/景别信息；2 摄影机运动有互斥选项；5 待敲与手已在门上的状态未定；6 机位、视线未定；7 机位和右手位置未定。
- 惊喜首轮适配：1 自定画幅及室内光源；2 “固定或轻微跟拍”、冷色顶光/侧光未确定；3 终点双手“可回到”未定；4 “准备或刚接触门”；5 从未注明灯光变化跳到“室内只有烛光”，且朝向未定；6 右手“已放下或自然”。
- 惊喜修正复测：1 左手“自然下垂或轻扶桌边”、视线两个目标；2 “侧面或正面固定，或缓慢跟拍”；3 左手/终点双手未定；4 待敲/贴门混用；5 身体朝桌/门未定，首帧提前成为闻声后停手而削弱反应变化；6 右手和视线未定。光源与画幅改成 TBD 是改善，但没有解决镜头设计决策。
- 交接基线：1 未给定自然光作为事实；2 机位二选一；3、4 面部近景同时要求桌面/双手与文件袋，需要重新确定裁切；5 机位二选一；6 机位及终点手部未定。
- 交接首轮适配：1 朝向、视线、背景和光源多个备选；2 视线未定；3 终点视线和光源未定；4 机位高度未定且视线与背景关系待整理；5 起点右手与终点触袋状态未定。
- 交接修正复测：1 视线未定；2 右手收回/放身侧及关键帧朝向未定；3 终点是否转向小周未定；4 以小周正面为主体却要求对坐老陈脸部部分可见，需明确轴线/构图；5 右手触袋/离袋与小周视线未定。

结论：适配增加了首帧构成、合并部分重复镜头；修正规则减少了凭空补灯光，但两份复测均未达 8/10，不能通过 GS01a 门槛。不能把 JSON 合法或镜头数量减少当成可直接生成视频。当前停止扩大 Drama 方法复用与正式资料库更新，保留工程候选。两种作品方向的真实质量差异与 MV 专用方法未验收，模拟接口只证明配置确实进入请求。

## 复现与恢复边界

隔离运行：`npm run prepare:test-vault` → `npm run launch:test-vault` → `npm run test:storyboard-apply`；`node scripts/launch-test-obsidian.mjs --restart` 后运行 `npm run test:storyboard-apply:reopen`，最后 `npm run stop:test-vault`。

真实探针必须显式 `--run`，从环境读取 `OBCANVAS_QUALITY_BASE_URL`、`OBCANVAS_QUALITY_MODEL` 和 `OBCANVAS_QUALITY_KEY`；命令为 `node --import tsx scripts/check-storyboard-quality.ts --run`，有真实文字请求。`--adapted-only` 仅用于同输入/同契约下规则修正复测。

未保存的方法表单需先保存，关闭插件不提供该表单的恢复；已保存配置及预览有持久化。跨笔记没有全库原子事务，逐镜写入和任务检查点可能部分成功；下次继续按固定 ID 校验并补齐，原笔记保留。任务已记为应用后删除镜头需恢复原笔记。源剧本或资产已变的历史任务保持过期，重新生成不会自动替换旧镜头。
