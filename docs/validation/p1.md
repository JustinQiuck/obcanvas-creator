# P1 / D06 镜头排序与选片验收

日期：2026-09-11。插件 0.2.0，实际宿主 Obsidian **1.13.7**。仅使用 `.local/test-vault/` 与 FFmpeg 合成的 H.264 MP4，不操作个人资料库或真实制作文件，不调用生成服务。

## 已完成的操作

1. 从中文界面建立一场戏的 A、B、C 三个镜头，保存拍摄理由、景别、机位、原提示词和来源备注。
2. A 用本地文件选择器复制一份视频，再通过文件拖放复制另一份；比较库内字节与原测试文件一致，状态为待选片，不自动采用。
3. A 采用第一份再换为第二份，第一份恢复候选，两份文件均保留。
4. C 关联 A 已有的第二份视频，保持同一素材 ID，但单独退回并填写原因；A 的采用不受影响。B 无视频，显示待素材。
5. 连续上移 C，两次写入后的正式顺序为 C、A、B；画布位置保持不变。
6. 用两个真实宿主视图提交过期的候选基线，第二次决定遭到拒绝，没有覆盖已保存选择。
7. 在真实 Vault.process 中注入选片写入失败，界面显示中文错误并保持原采用；恢复写入后重试成功。
8. 将采用视频移入测试库垃圾箱，A 继续显示已采用并独立提示素材缺失。恢复同位置测试文件后，A 的采用和 C 的退回原因仍在。
9. 素材改名和镜头正文编辑均保留选片决定、规划字段与镜头顺序。
10. 传入不支持的文件类型，显示中文错误，现有候选与采用保持不变。
11. 完整关闭并启动独立 Obsidian 后，核对三个镜头的顺序、规划与素材决定全部一致。

文件拖放测试向真实宿主的素材区域派发含 File 的 DataTransfer，覆盖导入处理；文件选择器使用 Playwright 的原生文件输入接口。没有另外测试从 Finder 发起系统级鼠标拖放。库外文件被复制入库，外置磁盘路径直连仍未实现。

## 实测修复

新增镜头现在还需将 ID 追加到场次顺序。测试暴露出创建过程中旧镜头表单仍可输入，导致快速填写时把新内容写入旧镜头。修复为创建／切换相关操作结束前禁用整张编辑表单，随后重新跑完三个镜头创建与选片流程；A、B、C 的 ID 和正文均正确。

回归清理所有标签页时还触发宿主的 `No tab group found.`，补充仅针对该错误的公开 API 回退，使空工作区仍可重新打开影视画布。重启测试还补充等待资料库扫描完成，避免仅恢复了选中 ID 时就过早读取场次记录。

## 当前边界

- 一个 Obsidian 资料库作为当前项目边界，内含多场次；尚无独立的跨资料库项目列表或迁移工具。
- 导入先复制，关联失败保留副本并显示位置；单文件大于 256 MB 先放入资料库再关联。本批技术属性只从播放器读取展示，尚未持久化。
- 已采用文件不能直接移除关联或换文件，先取消采用；单纯改名不取消采用。图片不作为视频候选。
- 本批保存每份候选的当前决定与当前退回原因，不提供决定历史日志；取消／恢复候选会清除当前退回原因。
- 采用表示选片决定，尚未标记剪辑完成。采用区间、关键帧截图与依赖复核属于 D07，Skill 导入属于 D08。
- 镜头层面的提示词与来源是可选文字；没有工作流参数管理、提交、轮询或收费调用。
