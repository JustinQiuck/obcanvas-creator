# P0-A 验收记录

本文件记录首批 P0-A 的历史验收范围；后续结果见 [P0-B](p0-b.md) 和 [P0-C](p0-c.md)。

结论：D01、D02、D03 已完成；在 macOS 的独立 Obsidian 1.13.7 实例中通过验证。D04–D08 尚未实施。

## 本批交付

- TypeScript／React 插件骨架、中文入口和自定义视图。
- 创建场次与镜头，编辑镜头标题、正文，打开对应笔记。
- 稳定 ID、版本校验、资料库事件刷新、保存反馈和受控更新。
- 两个视图并发编辑时检查冲突；保存失败保留输入，未保存草稿支持恢复。
- 独立测试资料库准备、启动、停止和宿主验收脚本。

原画布源码尚未复制。本批为新的宿主入口与保存层，不改变原画布项目，也未安装到私人资料库。

## 验证环境

- 实际宿主：Obsidian 1.13.7，macOS；插件最低版本设为本次验证过的 1.13.7。
- 开发运行时：Node.js 24.5.0。
- 依赖通过 `package-lock.json` 固定；没有指向原画布项目的外部包或绝对路径 import。
- 测试资料库：本仓库 `.local/test-vault/`。
- 测试实例配置：`.local/obsidian-profile/`；使用本机已有 Obsidian 程序与更新包。
- 本地调试仅连接测试实例，脚本在任何验收操作前检查资料库完整路径。

10 项实机检查覆盖：

1. 中文视图可加载，重复打开不会产生重复挂载。
2. 通过按钮创建场次、镜头，填写标题和正文后保存为笔记。
3. 外部文件修改触发视图更新，后续保存保留注释、其他属性与正文。
4. 两个真实插件视图修改同一字段时出现冲突提示，后保存者的输入保留。
5. 对测试镜头注入写入失败后，界面保留草稿；关闭视图再打开能恢复，解除失败后可保存。
6. 在资料库内改名后仍按稳定 ID 保存。
7. 插件卸载会卸载视图，重新加载后可读取已保存内容。
8. 未知版本草稿拒绝初始化，原备份文件不被覆盖；恢复有效测试备份后可重新加载。
9. 完整终止并重启独立 Obsidian 进程后，已保存的内容保持一致。
10. 通过“打开对应笔记”进入原生编辑器，修改正文后镜头卡同步更新。

## 复现步骤

在项目根目录执行，启动脚本目前仅支持 macOS：

```bash
npm ci
npm run typecheck
npm test
npm run prepare:test-vault
npm run launch:test-vault
npm run test:host
npm run launch:test-vault -- --restart
npm run test:host:reopen
npm run stop:test-vault
```

`test:host` 会在隔离库创建中性测试记录；再次运行保留之前的测试记录。`--reopen` 使用前一次验收生成的本地检查点。启动脚本使用项目内配置，与用户日常 Obsidian 实例分开。

## 限制

- 仅验证了上述 macOS／Obsidian 版本，没有验证 Windows、移动端或更早的 Obsidian。
- 目前界面是镜头记录编辑视图，尚未加入原画布平移、缩放、卡片拖动、素材预览和版本采用。
- 已验证保存内容重启恢复及关闭视图后的草稿恢复；不声称能恢复断电前尚未写入的最后几个输入字符。
- 模拟写入失败验证了错误处理路径，不代表已穷举硬盘故障或外置磁盘行为。
- 当前多个视图通过全库内的正式记录同步；独立弹出窗口、复杂跨进程文件竞争和大量镜头性能仍未验收。
