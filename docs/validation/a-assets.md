日期：2026-09-11。宿主：Obsidian 1.13.7。范围：A01–A05 的本地实现与隔离实机验证。

## 已通过

- 类型检查、构建、36 项逻辑测试（原有 28 项及新增 8 项）和差异格式检查。
- 内置 `production-asset-extractor` 通过 skill-creator 的 `quick_validate.py`；构建把技能正文打入插件，不依赖外部 Skill 目录。
- `npm run test:assets-ai`：8 项宿主检查；实际 HTTP 请求发往测试脚本临时启动的本机模拟接口。
- 完整退出并重启隔离 Obsidian 后，`npm run test:assets-ai:reopen`：2 项检查通过。
- `npm run test:free-canvas`：原有 9 项宿主流程通过，包括视频采用、镜头顺序、移除关系、草稿冲突和既有记录保留。

宿主资产流程覆盖：

1. 在中文设置页保存服务地址、模型和中性测试密钥，点击测试连接；请求路径、认证和消息格式正确，未发送剧本，原编辑草稿保留。
2. 从剧本启动内置 Skill；读取当前剧本和项目已有资产，结果先保存为清单，不增加正式资产笔记。
3. 修改清单名称并保存；确认后复用已有角色，创建场景和道具，自动关联剧本。
4. PNG 导入、指定参考用途、明确确认使用；仅导入不会完成准备，确认后对应待办消除。
5. 第二场次复用同一资产 ID；改名后两个剧本的引用不变。
6. 图片文件改名后关联更新；原文件内容修改触发复核，再次确认后恢复。
7. 模拟 401 显示中文错误，不创建新任务或改写剧本。
8. 测试前已有项目笔记逐字比较一致，包括已有视频采用记录。
9. 完整重启后模型配置、密钥读取、确认清单、资产引用和参考图用途恢复。
10. 确认清单的“绑定参考图”按钮可直接定位对应资产。

逻辑验证还覆盖原文依据无效、不存在的复用 ID、空道具结果、取消和超时、重复提交、剧本版本变化、部分写入后恢复、清单并发冲突以及旧记录格式兼容。

测试发现设置页在当前宿主中使用独立窗口，已修正测试目标；启动时需等待 `workspace.layoutReady` 后打开视图，已修正并复验。实现中修正了资产描述尚在编辑时参考图显示应读取最新记录的问题。

证据仅存于被忽略的 `.local/`：`a-assets-results.json`、`a-assets-results-reopen.json`、`a-assets-checkpoint.json`、`a-assets.png` 及原有 R1 回归结果。使用合成图片、中性剧本和模拟密钥，无正式资料库内容。

## 未验证与限制

- 用户选择“通用接口”，本次以 Chat Completions 兼容格式实现；尚未配置或调用真实模型服务。HTTP 模拟成功不能证明任意服务兼容，也不能证明真实提取准确率。
- 内置 Skill 的格式和打包已验证；由真实模型执行后的判断质量仍需使用者在清单中检查。
- 首版不发送参考图片给模型，不做生图／生视频、分镜分析、提示词生成、制作包、视频截图或续接。
- 任务草稿写入使用版本与内容比对；正式资产应用跨多文件按条目保存进度，失败可继续，不承诺跨文件事务。清单保存失败时需在当前窗口修正或重试后退出。
- `fingerprint` 使用文件路径、修改时间与大小检查变化，不是图像内容理解或密码学内容校验。
- A01–A05 的本地实现与模拟实机验证完成；真实服务验证和用户操作验收单独保留为未完成。
