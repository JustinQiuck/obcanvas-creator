# P0-C 库内素材验收

日期：2026-09-11。实际宿主 Obsidian **1.13.7**；只使用项目隔离资料库与 FFmpeg 合成测试图表，无真实制作素材或远程生成调用。

## 结果

D05 已完成。用户在镜头记录里点击“关联库内素材”，通过中文搜索选择器关联已有文件。笔记保存素材 ID 和库内相对路径，预览地址由宿主运行时解析；不需要手写属性。

- 从界面关联 640 × 360 PNG 参考图，确认实际 naturalWidth 与比例。
- 关联 640 × 360、2 秒、H.264 MP4；实际执行播放并观察 currentTime 前进，不以出现播放器外框视为通过。
- 同一路径重复关联不增副本；第二个镜头使用同一素材时复用已有 ID。
- 资料库中对素材文件夹改名，相关镜头路径全部更新，原有 ID 保留，图片仍可显示。
- 将测试视频移入测试库垃圾箱后，镜头显示“素材缺失”；通过中文选择器重新关联另一位置，视频恢复且素材 ID 保留。
- 关联一份扩展名为 MP4 的损坏测试文件，显示具体解码错误；移除关联后源文件仍存在。
- 完整重启应用后，原镜头素材路径和 ID 一致；图片和视频可重新读取。
- 与当前视频无关的素材变更通知不会重建正在播放的 video 元素；关闭视图后暂停播放并清除 src。
- 素材属性写入的逻辑检查覆盖未知字段／注释／正文保留、错误身份拒绝、重复 ID 及库外路径拒绝，普通镜头编辑保留新增素材字段。

## 证据与复现

命令见 [P0-B 验收](p0-b.md)。媒体夹具生成器为 `scripts/prepare-media-fixtures.mjs`，宿主脚本为 `scripts/test-canvas-media.mjs`；本地报告分别在 `.local/p0-bc-host-report.json` 和 `.local/p0-bc-reopen-report.json`。

自动化首次创建替代视频时误把宿主 TFile 对象作为 CDP 返回值，引发序列化错误；改为只等待创建完成，不传回宿主对象，随后重新完成缺失恢复检查。该问题属于测试脚本。

## 边界

- 本批通过中文选择器关联库内已有文件；拖入／复制外部文件、外置硬盘定位和离线访问尚未实施。
- 实测视频编码只包含 H.264 MP4。选择器接受的扩展名不代表所有编码都保证播放，无法解析会显示错误。
- 重命名自动更新依赖插件运行时的 Vault 事件。插件关闭期间搬动文件，需重新打开后手动重新关联。
- “重新关联”更新所有使用该素材 ID 的镜头；跨镜头多个笔记不是一次事务，遇到写入失败会报告错误，需要继续修复。
- 本批仅关联与预览素材。候选采用、待重做、采用区间和关键帧截图留在 D06／D07，不能将“已关联”理解为已采用或成片完成。
